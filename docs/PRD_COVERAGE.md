# Novel Library PRD 구현 현황

현재 구현률은 영역별 점수의 산술 평균인 기능 골격·로컬 핵심 흐름 기준 **약 90%**입니다. 5개 플랫폼 라이브 smoke와 2,000→10,000개 반복 스캔을 에뮬레이터 CI에서 시작했지만 실제 물리 기기 결과가 아직 없으므로 상용 완성도와는 별도로 관리합니다.

## 상용 구현률: 약 65%

현재 APK에서 플랫폼 결과와 직접 메타데이터를 관리할 수 있고 장기 작업에는 진행률 바를 표시합니다. CI에서 5개 플랫폼 공개 검색, 2천/1만 건 import, 1만 건 증분 스캔 10회 안정성 측정을 매일 시작하도록 구성했지만 첫 실제 물리 기기 결과 전이므로 **상용 배포 준비도는 약 65%로 유지**합니다. 정식 릴리즈 서명/스토어 배포, 물리 기기 성능과 접근성 검증은 여전히 남아 있습니다.

상용 100%를 한 번의 코드 변경만으로 정직하게 선언할 수는 없습니다. 외부 플랫폼은 실제 기기·네트워크에서 반복 검증해야 하고, 릴리즈 서명 키와 스토어 정책은 소유자가 결정해야 하며, 2,000~10,000개 파일 성능과 장시간 테스트에는 실제 실행 시간이 필요합니다. 남은 작업을 우선순위대로 계속 줄여 나갑니다.

이 수치는 “클래스나 스텁이 존재함”이 아니라, 실제 앱 기능으로 연결되고 저장/복구/테스트까지 어느 정도 준비되었는지를 기준으로 잡았습니다.

| 영역 | 예상 구현률 | 상태 |
| --- | ---: | --- |
| 프로젝트/빌드/CI | 99% | 단위 테스트, lint, APK, SHA-256, 품질 보고서 artifact와 `v*` 태그 prerelease 임시 APK 배포를 제공함. 정식 서명/스토어 배포는 아직 없음. |
| Room DB/마이그레이션 | 90% | 주요 테이블과 v1→v4 마이그레이션이 있고 플랫폼별 중복 listing을 정리한 뒤 복합 unique index를 생성함. 전체 migration 계측 테스트는 부족함. |
| TXT 폴더 선택/스캔 | 90% | SAF 탐색과 DB 반영을 분리하고 전체 파일을 한 트랜잭션에서 증분 판정해 999개 bind 한계를 피함. 2천/1만 건 에뮬레이터 기준 측정을 시작했으며 물리 기기 검증은 남음. |
| 로컬 라이브러리 UI | 94% | 핵심 목록·상세·대량 작업과 원문/결과 확인을 연결하고 스캔·백업·복원·내보내기·플랫폼 검색 진행률 바를 제공함. 전용 화면 분리는 남아 있음. |
| 관리 기능 | 93% | 사용자 데이터, 휴지통, 읽기 기록, 컬렉션, 태그와 직접 메타데이터 입력/잠금 흐름이 Room에 연결됨. |
| 스마트 컬렉션/추천 | 75% | 조건 판정과 “오늘 뭐 읽지?” 추천 엔진이 있음. 저장된 스마트 컬렉션 화면은 미완성. |
| 플랫폼 검색 | 90% | 5개 검색/상세 보강, 캐시·제외·취소, 작품별 사용자 검색어, 결과/오류 표시와 원문 열기를 구현함. 실패 시 기존 메타데이터를 보존하며 가짜 데이터는 만들지 않음. 실기기 검증은 필요함. |
| 백업/복원/내보내기 | 90% | TXT 본문을 제외한 ZIP/JSON/CSV와 크기 제한·검증을 거치는 병합 복원, 사용자 데이터 복원 Repository 로직을 구현함. 컬렉션 전용 복원은 남아 있음. |
| 진단/설정 | 90% | 하위 폴더/Wi-Fi/리뷰 설정을 DataStore에 저장하고 앱·DB·권한 진단 표시, 복사와 권한 설정 이동을 UI에 연결함. 플랫폼 순서 UI와 캐시 정리는 남아 있음. |
| 테스트 | 85% | JVM/lint/UI/migration 외에 2천→1만 건 import, 1만 건 증분 10회와 5개 플랫폼 live smoke를 에뮬레이터 CI 및 매일 schedule에서 실행함. 실패는 보고서로 수집하며 물리 기기 검증은 남음. |

## 다음 우선순위

1. 상세 화면과 직접 정보 수정 화면 구현
2. 일괄 선택/일괄 편집 UI 구현
3. 휴지통 화면과 복원 UI 구현
4. 컬렉션/스마트 컬렉션 저장 및 화면 연결
5. 컬렉션/설정/플랫폼 정보까지 포함하는 전체 백업 및 컬렉션 전용 복원 구현
6. Room migration/scanner/repository 테스트 추가
7. GitHub Actions APK 빌드 결과 확인 후 dependency/build 오류 수정
8. 공개 HTML 파서를 실기기에서 검증하고 변경된 선택자·접근 제한을 플랫폼별로 보수
